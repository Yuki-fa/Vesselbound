# 長期の組合せを選ぶplanner

既定は第2段。山場の先読み、重みの学習、未使用の種での比較は[PLANNER_R2.md](PLANNER_R2.md)を参照。以下の固定係数と評価式は `--planner-stage r1` の保存用仕様。

対象はNodeの周回ボットのみ。本体JS・index.html・マスターxlsx・内蔵CSVは編集しない。戦闘の実装は追加せず、lookaheadと同じ本体computeBattleを使う。新ルールの本体操作（交換店・還魂・祝福）もそのまま呼ぶ。Node専用ファイルのためindex.htmlの読み込み・キャッシュ版追加は不要。

```sh
node tools/balance_sim/synergy.js --out tools/balance_sim/out
node tools/balance_sim/run_bot.js --runs 200 --policy lookahead,planner --seed 1 --workers 4 --tower-boon on --out tools/balance_sim/out
node tools/balance_sim/run_bot_selftest.js --input tools/balance_sim/out
node tools/balance_sim/run_report.js --input tools/balance_sim/out
```

旧出力は全28ファイルを `out_before_planner/` にコピーし、バイト一致を確認してからoutを更新した。試走・制御フィクスチャは `/tmp` だけに出し、通常成績へ混ぜない。所要時間はmetaへ分離し、runs.jsonlは同じ種で再現できる。

## 抽出

`synergy.js` は `sheet_data.js` を経由してchar/card/enchant/ring/itemの各行をヘッダ名で読む。実行中のカードも同じextractを呼び、合体・祝福等で変わった本文とキーワードを読む。名前で効果を決める例外辞書は持たない。

- `produces`: マナ、血、召喚、死亡、負傷、攻撃、結界、毒、各色、キーワード、接続、ATK/HP強化、各誘発効果。
- `consumes`: Nマナ毎・マナ/血比例、封印/解放、死亡/召喚/負傷/攻撃の観測、色指定、キーワード数等。
- `local`: 同じキャラクターに接続している時だけ有効な需要。
- `global`: 全体への自傷、全体の追加攻撃等、他のキャラへ届く供給。
- `unknown`: 条件語だけを拾って全文対応にしないため、未対応の作用・補足を文節単位で残す。

キーワード定義はkeywordシートの名前に限定する。効果文が空の専用強化だけは名前が定義と一致すれば本当のキーワードとして扱う。「活性化」「マナの種」のような効果のある強化名はキーワードにならない。召喚を観測するだけの「ナーガ」を召喚の供給にはしない。敵へ与える結界やダメージを味方への供給と混ぜない。

`synergy_cards.csv` は全行の役割・根拠の規則・局所/全体範囲を出す。`synergy_unknown.csv` は未対応部分を含む行の全文を出す。未実装・荷物・文節だけ未対応の行も含める。抽出は戦闘効果の完全なパーサーではなくAIの近似で、効果の発動・値は本体が決める。

## 評価と型

`planner.js` のLIMITSに係数を集約する。目先は240×勝率＋40×log(1+残HP/max(40,敵HP))＋4×log(1+与ダメ/max(40,敵HP))。ライフ1は勝率を400倍。将来は0.6×既存の噛み合い＋1.2×未成立の見込み＋0.5×型への近さ＋祝福の将来価値。候補絞込みに使う役割加点は0.3倍に抑える。

9種はマナ、血と解放、召喚と死亡、色、毒、結界、負傷、連続攻撃、キーワードと接続。取得・交換・還魂・配置・祝福の後で成立度を更新する。温度max(0.5,2.5−St×0.5)のsoftmaxで序盤を広く、後半を集中させ、前の重み55%と新しい推定45%を混ぜる。候補試行中は重みを変えない。方針の履歴はcontextだけに持ち、本体Gやセーブへ追加しない。

出撃本体と本体が判定した接続網・装備指輪を1、予備/未接続を0.22、未使用アイテムを0.35として扱う。本体限定の相乗りは接続先を照合。通常の死亡や被弾は弱い供給で、それだけで完成判定にしない。同じ型への加点はlogで飽和させる。トリプルの収集加点は無効。本体の通常操作による合体はそのまま。

## 入手見込み

本体の残り旅程から報酬と街を列挙する。現在の実装済みプール・除外・残在庫を使い、`_rewardGradeBuckets` / `_rewardGradeWeights` / `_rewardRarityWeights` の確率を分解する。カテゴリはdrawPanelと同じ1/2、序盤のレア制限・ステージ別グレード・黄金の指輪も反映。未来の実ラン乱数や店の実際の在庫を先取りしない。

P=1−Π(1−1枠で相手を引く確率)^実効提示数。実効提示数は報酬5×0.35、店3×0.55に、将来St差ごと0.88、機会の距離ごと0.97の割引を掛ける。候補を選べる枚数と途中敗退の危険を割り引く近似。既にある相手は直接照合し、未成立の役割だけPを用いた資産価値を付ける。

枠の独立近似なので、同一提示の重複不可、封印上限、高レア上限、カテゴリ保証、ボス置換、将来の指輪/道具の抽選は完全には再演しない。将来の取得による在庫の変化も追わない。死亡の敵/味方、マナの時系列、封印に必要な血の量は粗い近似。次の山場で仮想の完成盤面を試す追加探索は採用しない。

## 操作・記録・検査

lookahead.jsのdecision/apply/配置探索を共用し、plannerだけに将来点を付ける。キャッシュはコアの目先の値だけを保存し、その都度同じ固定の計画で将来点を計算する。報酬の絞込み、交換、還魂、指輪、配置、祝福の選択で共用。祝福は既存盤面へ遡及せず、残りの入手機会に対する価値。80G温存、1訪問2回まで。再抽選は取得改善0.8未満、本体の権利内で最大3回。

探索上限はlookaheadと共通（敵3、報酬5、配置1+前後衛、swap5+分散4、改善2、還魂3、完成配置4）。交換は全合法候補。実ランを変えるのは本体の合法な操作だけ。

`planner_selftest.js` をrun_bot_selftestから呼ぶ。主要カードの抽出、未所持のマナ生成を見込んで活性化を取る実コアの制御例、後のシルフとの接続、型の切替、確率と序盤制限、接続先、G/提示/乱数の隔離を検査する。通常のJSONLでも投資・型の切替・組合せを検査し、同じ種の再実行と別ランを挟んだ再実行を全内容比較する。

初回比較でコア上限の打切りに達する組合せが現れ、ボットの終了処理が最後の資源記録を飛ばしていた。timeoutの分岐でも戦闘と同数の資源記録を残すよう修正した。初回設定・種197を成績へ混ぜない制御例として再実行し、出口を回帰検査する。コアの上限・勝敗・戦闘処理は変更しない。

報告は最終盤面の型（全終了/クリアを分ける）、実戦開始時の組合せ、目先を犠牲にした選択と後の相手の取得を追う。型の成立は静的な役割判定で、全効果の発動・因果効果ではない。後から相手を引けなかった投資も隠さない。詳細な数値・未対応数・成績は生成した `out/RUN_REPORT.md` に記録する。
