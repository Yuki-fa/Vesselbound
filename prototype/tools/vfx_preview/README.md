# VFXの試作集・改修版

指定30項目を、魂の3種・オーラの比較・全体攻撃の3案を分けた36項目として用意した。途中の作業ツリーとSE候補を引き継ぎ、描画を共通部品から作り直した。

ゲーム本体への組み込み前のプレビュー。本体のindex.html・既存JS・assets.js・docs・AGENTS.md・シートはこの作業で変更していない。

## 開き方と操作

tools/vfx_preview.htmlを直接開く。file://対応、ビルド不要。prototype/でローカルサーバーを用意すれば、http://127.0.0.1:5500/tools/vfx_preview.htmlでも開く。サーバーの例：

    python3 -m http.server 5500 --bind 127.0.0.1

左の一覧を押すと、演出ごとに合う発生元と対象を自動で選んで再生する。「もう一度」は同じ設定、「全部を順に再生」は全36項目を巡回する。カードを押して対象を選び直せる。「クリック操作」を発生元へ切り替えれば発生元を変更できる。金枠＝発生元、青枠＝対象。「自動選択に戻す」で初期配置に戻る。

敵から味方へも再生できる。盤面は3840×2160の設計座標を縮小表示する。数字6/8と毒札は仮値で、IMPACTは数値との同期点。戦闘計算はしていない。「見た目の基準」には利用者が指定したC018・S008・C043のコマを並べた。

SEは各項目3候補。プルダウン変更、または候補一覧の「この候補を聴く」で試聴する。原本の場所・原音とコピーの尺・切出し位置を画面に表示。「選択を保存」はSE・元パス・音量・速さ・大きさのJSONを保存する。候補の選択はプレビュー専用localStorageにも保持する。

## VbFx.play

通常のscriptタグでfx_lab.jsを読み込む。ES Modules・fetch・ビルドは不要。assets.jsのgetEffectVfxPathがあればC053登録の参照に使うが、描画部品自身はassets.jsを必須にしない。

プレビューで実行できる呼び方：

    var source = document.querySelector('[data-side="ally"]');
    var targets = [document.querySelector('[data-side="enemy"]')];
    VbFx.play('banshee', {
      source: VbFx.rect(source),
      targets: targets.map(VbFx.rect),
      side: 'ally',
      allies: Array.from(document.querySelectorAll('[data-side="ally"]')).map(VbFx.rect),
      enemies: Array.from(document.querySelectorAll('[data-side="enemy"]')).map(VbFx.rect),
      onImpact: function (targetIndex) {
        // この対象の、確定済みダメージ数値・表示HPをここで見せる。
      }
    }).then(function (result) {
      // VFXと一時styleが消えた。次の異なる効果へ進める。
    });

矩形はgetBoundingClientRectの形の画面座標。DOMRectそのものも受け付ける。DOMを揺らす・色を変える項目ではVbFx.rect(element)を推奨する。この補助関数は矩形にelement参照を付ける。素の矩形では中心のelementFromPointからカードを探すため、他のDOMに隠れたカードには参照を明示する。

sideは発生元の陣営。相手の陣営の矩形から敵方向を決める。targetsの順がonImpactの添字になり、各対象1回だけ呼ぶ。ダメージ・毒・HPの計算はしない。

Promiseは描画・一時style・追加DOMを片付けてから解決する。戻り値はname / cancelled / impacts / assetErrors。VbFx.stopAll()は片付けてcancelled:trueで解決する。onImpactが例外を投げた場合は片付け後にrejectする。rAFが止まった場合も番人タイマーで終わる。

styleは再生ごとに所有を管理し、重なった再生が逆順に終わっても原値を保つ。VbFx.activeCount()は再生数、VbFx.snapshot()は尺・描画時刻・予定命中時刻・DPRを返す。

## 承認後の本体への接続点

承認後にだけ、index.htmlへ読込を追加し、render.jsにDOM矩形へ変換する共通アダプターを1か所置く。PvEのbattle.jsとオンラインのboard.jsへ描画を複製しない。

- 飛翔効果はpresent_events.jsのpresentDamageEventが持つonImpactの流れへ接続する。api.applyHp(target, ev.hpAfter)とupdateUnitDamageUiを命中時に進め、既存playHitVfxAtRectのlabelOnlyなどで数字を見せる。
- 複数対象はコアが確定したdamageKind / batchとpresentDamageGroupKeyの束を使い、targetsの添字とイベントを対応付ける。onImpactから対象ごとにapplyHitして戦闘処理を作り直さない。
- 通常の全体攻撃はpresentAttackContactVfxEventの同時命中を保つ。3案のonImpactは同じ瞬間に全員を呼ぶ。VFX終了待ちで数字を1体ずつ遅らせない。
- 次の異なる固有効果へ進む時はPromise完了を待つ。同じ効果の複数対象はplayを1回にまとめる。
- リッチのsourceには、死んだ味方の最後の矩形を渡す。
- ワームのonImpactは波がこの敵を通過した合図。毒の有無と毒ダメージはコアのイベントに従う。
- ヴリコラカスのプレビューはオーラ→K020の連続見本。本体の復活はpresentReviveEvent / playReviveVfxを通し、付与と復活のイベントを混同しない。
- ドラゴネットの絵替えはpreview.jsが霧の濃い命中点で行う。本体では確定した変化先の描画へ接続する。
- SEは本体のplaySfxと同種同時音の重複防止へ接続する。今回のnew Audioはプレビュー専用。
- 新しい固有VFXを本体へ入れる時は演出パリティへシナリオを追加する。

## 共通描画部品・決めた値

真上から見た円・同心円・文様・渦・カード外周が基本。炎や魂の移動も盤面内の平面的な軌跡。横から見た立ち上がる炎、光の柱、地面の奥行き、足元の楕円は使わない。

- texture / stamp：白い芯→色→柔らかい減衰、事前blur、lighter加算。暗い煙は通常合成。
- noise / fractal：値ノイズ3層。流体の密度・輪郭・斬撃の太さ・枝の揺らぎに使う。
- particles / fluid：個体ごとの寿命・速度・遅延・サイズ・摩擦・回転・ちらつき。通常数十〜百数十粒。インプは各カードから22粒ずつ。
- ring / magic / perimeter：乱れた波面、40枚の外周文様・32の記号・8枚の花弁、真上から見たカード外周。
- trailDot：65msの指数減衰で残光を残す。残光は柔らかい等倍層、芯と文様はDPR付きの主canvasで描く。
- charge / burst / impactFx：短い溜め→速い炸裂→減速する粒子と余韻。命中の白い核・衝撃輪は300ms以内。カードの明るさは140ms程度だけ上げる。
- 座標は画面矩形に一致させ、DOMの移動は矩形幅÷offsetWidthで縮尺を補正する。

| 設定 | 現在値 |
| --- | --- |
| VbFx.settings.speed / size / particles / shake | 各1 |
| VbFx.settings.dprMax | 2 |
| VbFx.settings.seed | null。撮影では53に固定 |
| 残光の減衰時定数 | 65ms |
| 通常の尺上限 / 画面端まで届く波の上限 | 1500ms / 2000ms |
| SEの初期音量 | 32% |

playの追加オプションspeed / size / seedでも指定可能。スピードを下げても尺上限を超えない。「全部を順に再生」はSEの尾も待つ。

## SEの選定

指定フォルダの13,723音声をファイル名・フォルダ名で調べ、関連キーワードとafinfo等による尺で絞った。2,693件の尺を確認し、0.2〜2秒の1,205件を中心に選定。聴感による最終採用は未確認。

原本は変更せず、45ファイルを48kHz・16bit PCM WAVへ変換／コピー。ピーク約−1dBFS、コピー0.2〜1.95秒。長い先頭無音を詰め、長い尾は切り出し、切った末尾は30msフェード。同じ音は複数の演出で共有する。

根・霧・金色・虹は名前が一致する短音が少なく、活性化・風・白魔法・鐘を代替候補にした。全36項目の3候補のファイル名・尺と45原本の完全な場所は [se/README.md](se/README.md) に記載。画面にも表示する。

## 検査

追加した全JSへnode --checkを実行。tools/vfx_preview.html?verify=1では全36演出、逆方向7演出、同時再生、onImpactからの追加再生、停止、例外、rAF停止、無効な矩形、SE45ファイルを検査する。

各演出で命中数・重複・素材読込・Promise終了・カードと盤面のstyle復元・レイヤー消去を確認。音量0では鳴らさず音声メタデータを別に読む。結果は画面のPASS／FAILとJSONで確認できる。

撮影可能な環境ではnode tools/vfx_preview/check_headless.jsを実行する。file/httpの通常再生を検査し、fileの各演出を4段階でshotsへ保存する。各段階は固定seedの別再生で、rAF描画直後にJSを止めて撮影する。時刻が取れない場合は失敗にする。結果はheadless_results.json、成功時の比較一覧はshots/index.html。
