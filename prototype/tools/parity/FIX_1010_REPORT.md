## 1. アラッサスの呪詛死と攻撃中の死亡

攻撃効果で攻撃者が死亡し、味方が残って戦闘が続く場合、通常の `attack` イベントが出ない。
従来の先出しモーション計画は後続の `attack` を必要としたため、踏み込みを始められず薙ぎ払いだけが先に出た。
さらに呪詛は `curse_death` だけを出し、通常の `death` が無い。そのため通常の死亡演出へ接続されなかった。

共通の `present.js` が、攻撃効果中に中断された攻撃へ表示専用の既存 `attack(effectOnly)` を補う。
これで既存の25%地点への踏み込みにVFXを同期し、戻りを終えてから通常の死亡演出へ進む。
呪詛には共通の死亡通知も補い、`present_events.js` で表示HPを0へ進める。
コアから渡す攻撃対象のヒントは表示用で、死亡判定・ダメージ・勝敗は再計算しない。
根性で耐えた呪詛には死亡演出を補わず、コアが決着時に出す表示専用攻撃とも二重にしない。

反撃死・懺悔による攻撃効果の自傷死・帰滅の反撃死・呪詛と根性も同じ再現スクリプトに含めた。
42盤面のコアイベントと最終状態は変更前に一致。比較から除外するのは `effect_flash.targetId` の表示ヒントだけ。
Nodeでは、中断時の踏み込み計画、通常死亡前の戻り、反撃後の通常死亡、根性で耐えた呪詛へ死亡を補わないことを確認した。
実画面の倒れ方とVFXの位置・時刻はChromeで未確認。

## 2. 攻撃効果の解決順

`core.js` で攻撃時のダメージ処理を登録順に保留し、非ダメージ処理を終えてから解決する。
本人・強化・反復・味方の攻撃を観測する効果・攻撃で到達したマナ閾値を共通の順序へ通す。
非ダメージ同士とダメージ同士の既存順を保ち、嵐の指輪は後者の最後で到達後のマナを読む。
ダメージから派生する負傷・死亡などは、その原因に続く既存順で処理する。
ダメージから得たマナも同じ攻撃内で処理し、次の手番へ持ち越さない。
先行する変身で発動済みの効果が消えないよう定義を保持し、対象と数値は解決時の盤面から読む。
保留した関数は戦闘状態に残さない。

結果が変わる例：アラッサス＋衝撃波＋魔族の魂＋竜の契約。

| 順序 | 変更前 | 変更後 |
| --- | --- | --- |
| 攻撃効果 | 全体4 → 魂12 → 弱体1 → 竜9 | 弱体1 → 全体5 → 魂13 → 竜9 |
| 接触攻撃 | 8 | 8 |
| HP200の敵の残りHP | 167 | 165 |

他の結果が変わる例として、サイレンに召喚効果を加えると、先に出た召喚体も後続の「全キャラクター」ダメージに含まれ、今回の検査ではHP1の召喚体が死亡する。
弱体・分類内の順序・反復・マナ閾値・指輪・自傷からの負傷マナ・召喚・変身・味方攻撃の誘発・毒による修正死と死亡誘発を回帰検査で確認した。

`core_refactor_diff` の95キャラクターは不一致0。
追加の複合盤面は、弱体の移動とそれによる上記2点の差だけを期待値へ反映し、他の全イベント・勝敗・最終状態を一致させた。

## Chrome検査の第1回報告への修正（2026-10-10）

受領した失敗：`attack_lifecycle_1010_check` の `1回/初撃で対象死亡/pve/1: 同じIDが2枚見えない`。

死亡へ切り替える `playUnitDeathBurn()` が元枠の `visibility` を隠す時、`.slot` の
`transition: all .18s` が残っていた。CSSの `visible → hidden` は遷移の終端まで見えるため、
死亡用の複製を追加した後も元カードが180ms見えていた。攻撃モーションでは遷移を止めていたが、
初撃で倒れた対象の死亡開始には同じ対策が無かった。

共通レンダラーで死亡用カードを確保した後、元枠だけ `transition: none !important` にしてから隠す。
PvE・オンラインとも `presentDeathBatch` → `_playDeathBurnOnce` → `playUnitDeathBurn` を通るため、
両方へ同じ修正が適用される。通常死亡の焼失と衰弱死の波打ち、位置・寸法・尺・効果音は変えない。
復活時のカードは既存の再描画で新しく作られ、元枠へ付けた遷移停止を引き継がない。
コア、受け口、再戦・敗北、データは変更していない。

同じ再現スクリプトに、実際の死亡開始・演出選択関数とCSSの可視遷移を使う仮DOM検査を追加した。
味方／敵 × 通常死亡／衰弱死 × 1／2／3倍の12通りで、旧版の重複を検出し、修正版は各時刻で1枚以下を確認。
修正前の現行コードにもこの検査を適用すると失敗し、レンダラーの修正後に合格した。
既存の42盤面の戦闘結果一致、攻撃中断時の計画、モーション重複の回帰検査も引き続き合格した。

ブラウザの可視判定・数える要素・重複を許さない判定は維持した。
失敗時には重複ID・フレーム・要素のクラス・計算済みの可視状態・遷移・座標を出力する。
PvEの検査用再生の終了には、実際の `battlePhase()` と同じく、外側の再生を閉じた後の
`requestBattleCompact()` を追加した。再生途中の全フレーム監視はそのまま行う。

変更ファイルは `js/engine/render.js`、その `?v=` だけを更新した `index.html`、
`tools/parity/attack_lifecycle_1010_check.js`、本報告の4本。
検査ファイルの追加は無く、`NEW_CHECKS_1010.txt` の登録はそのまま使える。コミットはしていない。

## Chrome検査の第2回報告への修正（2026-10-10）

原因は新規検査の正規表現。ChromeのCSSOMが返す `translate(42px, -85px)` のような
カンマ後の空白を認めず、可視の複製が移動していても不合格になっていた。

呪詛ケースの失敗表示にはPvE／オンライン・速度・炎開始時の記録を含め、原因を追えるようにした。
